## 用户需求

B26 阶段 3 的 QA 子图评审时序由「方案甲（三评审节点并行）」改为「方案乙（两级时序）」：内容设计评审前置为编排门禁，通过后再生成讲解/习题并并行评审。用户拍板理由：符合 Agent 的 ReAct 范式（先规划 → 评审规划 → 再执行 → 评审产物），且编排阶段返工（改结构清单）成本远低于生成后重写正文。

## 本次落档内容

1. QA 子图结构改为两级：

- 第一级（编排层）：生成 ContentDocument → structureChecker（纯代码，先行失败快）→ 内容设计评审 → 条件边（major → fix 编排带缺陷清单 → 回评审，循环上限内；pass → 进入第二级）
- 第二级（呈现层）：并行派生讲解 + 习题 → 讲解评审 ‖ 练习评审（并行，独立上下文）→ aggregator → 条件边（pass → END/人工节点；minor → 放行+标记；major → fix 对应产物 → 回对应评审）
- 标注范式映射：第一级 = ReAct「规划-评审规划」，第二级 = 「执行-评审产物」

2. 角色 × 维度矩阵不变（内容设计=结构+一致性+覆盖度；讲解=事实+清晰度+形式偏好；练习=可解性+难度+匹配+依据），仅时序变化
3. 补设计理由：先锁骨架再填内容；major 编排缺陷只重跑编排级、呈现级不重跑
4. 演进锚点表人工中断行补衔接点说明（interrupt 落点=两级之间编排确认 + 终稿后终稿确认，时机不变）
5. 成本口径微调说明（调用次数不变，编排返工不波及呈现级）
6. README 总表 B26 条目同步补「两级评审时序」
