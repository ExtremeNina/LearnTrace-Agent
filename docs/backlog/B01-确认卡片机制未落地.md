# B01 确认卡片（Human-in-the-loop）未落地

- 优先级：P1　|　模块：会话 / 题目 / 网课　|　来源：Spec 轴（PRD §7/§9/§3.2）+ Standards 轴
- 状态：待办

## 问题
PRD §7/§9 要求 Agent 涉及创建/修改/删除用户数据的操作必须先发对话内确认卡片、用户确认后才执行。当前：
- `Message` 实体仅预留 confirmStatus 字段，无下发/响应/持久化逻辑；`ChatEvent` 无 card 类型
- `QuestionSaveTool.saveQuestion` 调用即落库（saveFromConversation 直接 insert）
- `NoteGenerationService.generateAndSaveNote` 流水线生成后直接入库（注释自认“确认卡片方针确定后再补”）

## 影响
违反 PRD 核心原则（Human-in-the-loop），用户数据可能被 AI 误写。

## 建议
按 agent.md 待办 1 推进：先拍板方针（整篇一张卡 vs 分节确认、确认前可否预览），再实现卡片下发/响应事件与持久化。设计前提：AI 重新生成不得静默覆盖用户已修改的笔记。
