# B03 相似题确认后无法保存（saveQuestion 强依赖带图消息）

- 优先级：P1　|　模块：题目 / RAG　|　来源：Spec 轴（PRD §8）
- 状态：已完成（2026-10-02，同日按用户拍板修正存储模型）

## 问题
`QuestionSaveTool.saveQuestion` → `QuestionServiceImpl.saveFromConversation` 强依赖“会话内最近一条带 imageUrl 的用户消息”作为题目来源（无图消息直接 return false）。RAG 相似题流程（rag_search 召回 → LLM 生成 → 用户确认保存）生成的相似题是纯文字、无图，走该工具保存必然失败。

## 影响
相似题 RAG 闭环最后一步断裂：能生成、不能入库。

## 整改（2026-10-02 v2，按用户拍板的存储模型）
**相似题回到独立的 `similar_question` 表**（首版曾入 question_record 无图分支，同日修正）：
- `saveFromConversation` 按来源分派：`photo` → question_record（带图，原行为）；`text`（AI 相似题 / 手打题）→
  similar_question（sourceQuestionId 可空 + conversationId 溯源，新增 subject 列）。
- `saveQuestion` 工具增加可选 `sourceQuestionId` 参数；rag_search 输出为拍照题目外露「题目ID」供模型回填。
- 列表合并：`QuestionRecordMapper` UNION 查询输出统一 `QuestionItemVO`（source = photo / similar_ai），
  前端拍照记录页合并展示并以「AI 生成」徽标区分；编辑 / 删除 / 详情按 source 分派双表。
- 表结构（`sql/similar_question_model.sql`）：similar_question.source_question_id 改可空、补 subject 列；
  question_record.image_oss_key 恢复 NOT NULL（回归纯拍照记录语义）。
- 向量化：相似题以 `sq:{id}` 文档 ID 入库（与拍照题目 `q:{id}` 区分两表自增主键），
  RAG 可再次召回；补漏任务覆盖 similar_question。
- 前端知识联系面板的选题列表仅保留拍照题目（后端按 question_record 解析链接标题）。
