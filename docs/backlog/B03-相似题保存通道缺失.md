# B03 相似题确认后无法保存（saveQuestion 强依赖带图消息）

- 优先级：P1　|　模块：题目 / RAG　|　来源：Spec 轴（PRD §8）
- 状态：已完成（2026-10-02）

## 问题
`QuestionSaveTool.saveQuestion` → `QuestionServiceImpl.saveFromConversation` 强依赖“会话内最近一条带 imageUrl 的用户消息”作为题目来源（无图消息直接 return false）。RAG 相似题流程（rag_search 召回 → LLM 生成 → 用户确认保存）生成的相似题是纯文字、无图，走该工具保存必然失败。

## 影响
相似题 RAG 闭环最后一步断裂：能生成、不能入库。

## 整改（2026-10-02）
采用 backlog 两条建议的组合——来源标记 + 无图分支：
- `saveFromConversation` 增加 `source` 参数：`photo` = 拍照题目（维持原行为，自动关联最近带图消息）；
  `text` = 纯文字题目（RAG 相似题 / 手打题），imageOssKey 为 NULL，不查图片消息（避免旧图错挂到相似题上）。
- `QuestionSaveTool` 增加 source 必填参数并更新工具描述；BASE_PROMPT / QUESTION_PROMPT 同步更新保存指引。
- 表结构：`question_record.image_oss_key` 改为可 NULL（`sql/question_record_image_optional.sql`，已对库执行）；
  前端 `QuestionRecordInfo.imageOssKey` 类型放宽为 `string | null`（列表 / 详情已有 v-if 守卫）。
- 无图题目保存后同样向量化入库，RAG 可再次召回，闭环完整。
- 测试：text 来源保存（无图、不挂旧图、向量化）、photo 来源维持原行为。
