## 核心思想（用户原文）

> 视频只是输入，统一内容模型才是核心资产。确定性工作交给 Workflow / Service，非确定性决策交给 Agent。

四层解耦：媒体处理（FFmpeg/ASR/MQ，确定性）→ 原始转写（Raw Transcript，事实层不被 AI 修改）→ 内容理解（ContentDocument 语义层）→ 呈现（笔记 / Markdown / Word / PPT / 练习题，Renderer 派生）。

## 分析结论（2026-10-05，对照现状）

**认同**：确定性/非确定性边界（现状已遵循）；三层内容模型——当前最大缺口正是中间语义层（course_transcript_segment 直接单次 LLM 生成笔记，无 ContentDocument，换输出格式要重跑 LLM、知识点无独立实体、AI 对话无法引用章节）；不做大一统 Agent；人机协作确认（已有硬性规范）。

**修正**：
- MQ 跨队列链式编排（fan-in 聚合）当前规模不必要——单消费者内 courseExecutor 并行（帧 OCR 先例）天然有聚合点，拿 90% 收益付 10% 复杂度
- Map-Reduce 按转写字数**自适应**（阈值约 1.5 万字），不给 30min 级常见场景强加多倍 LLM 成本；跨 chunk 概念连续性是分段摘要的新风险
- ReAct 内容工具：`extractKnowledgePoints` 类工具若最终只映射固定 2-3 种编排，是 Renderer 参数而非 Agent；工具返回「句柄/摘要」而非大段产物（token 控制）；产物类生成走持久化
- 状态机：不新立 video_task 表——course 实体即任务载体，细化 status/加 stage 字段 + 复用 B11 推送基建（AgentEventPushService + 事件）即可

**文档未覆盖、落地要撞上的问题**：ContentDocument 生成时点建议**惰性**（首次消费触发，B13 简报模式）；多输入源归一（B19 PDF、笔记向量化应产出同一模型，否则语义层只服务视频）；ASR 无 speaker/confidence（保留列允许 NULL）。

## 阶段 1：产物校验 + 流水线细粒度进度（低成本高收益，先行）

- **产物校验 + 一次重试**：NoteGenerationService 生成后代码级校验——四段标题齐全、章节时间线时间戳存在于转写分段集合、知识点非空、正文/转写字数比合理；不合格带缺陷说明重生成一次，再不合格降级落库并标记；后续可加引用对齐（知识点段落回检索转写原文，低相似判无据）。**定位：零成本第一道闸，阶段 3 QA 子图的结构规范维度由此升级为独立评审节点**
- **进度状态机**：course.status 细化（AUDIO_EXTRACTED / TRANSCRIBING / ANALYZING / NOTE_GENERATING…）+ 进度清单事件（✓/●/○）复用 AgentEventPushService 推送
- **转写修正管线（2026-10-07 拍板，接在 ASR 之后、内容理解之前）**：ASR 错误（同音词 / 术语 / 人名）会级联污染笔记与习题，源头治理——
  - **两层机制**：① LLM 审校节点（DeepSeek，利用内置常理）扫出候选修正清单（词 / 位置 / 理由）；② 佐证确认——任一独立佐证命中即高置信：帧 OCR 交叉验证（老师 PPT 文字 vs ASR 听写，双通道白送）、领域词典（按 subject）、ASR 重解码一致
  - **分层处理（免打扰 UX，不做逐词点击）**：有佐证 → **自动应用**（用户无感，原文永久保留 + 修正留痕可审计）；无佐证 → 聚合为转写页顶部「⚠️ N 处疑似转写错误」**批量确认入口**（用户有闲时一次处理，可全采纳 / 全忽略，不看不影响下游——下游按「可疑保留原文」消费）
  - 例子：video5 转写「养流效应」→ LLM 候选「洋流」→ [09:05] 帧 OCR 命中「洋流中断」→ 自动应用；「雪球地壳假说」→ 无佐证 → 进批量清单
  - 边界：**Raw Transcript 不可变原则不破**——「不可变」指不覆盖原始结果，修正以留痕叠加方式呈现（下游读修正版，原始可追溯）；DeepSeek 只做候选生成不做确认（长尾实体有反向误改风险），确认权在佐证源
- 范围：网课流水线 + B11 对话转写共用校验与修正管线

- **第一步 · SAA 兼容性 spike**：引入 `spring-ai-alibaba-graph-core` 跑双节点 demo，验证 SAA 1.1.x ↔ Spring AI 1.1.8 + DeepSeek（OpenAI 兼容端点）共存；通过 → 按下述落地；不过 → 回退自研轻量状态机（course 表 stage 字段 + 幂等阶段方法，节点函数化已就绪保证可互换）
- **Graph 化迁移**：把阶段 2 的节点函数编排为 StateGraph——顺序边（现有流程）、**条件边**（产物校验 QA 回退循环，从阶段 1 的方法内循环迁移为真正的循环边）、**并行边**（音频 ‖ 画面通道真并行，修正现状串行）、进度事件沿用 AgentEventPushService（COURSE 事件按 stage 推送，B11 基建复用）；QA 子图**前置「转写审校」节点**（即阶段 1 修正管线的 LLM 候选生成位，位于内容理解之前——源头干净则下游评审误报更少）
- **核心交付物 · 多角色评审 QA 子图（2026-10-06 拍板设计）**：生成内容的正确性与「是否合乎用户方向」由多个评审 Agent 在图内多维度评估——
  - **子图结构（两级评审时序，2026-10-07 拍板选方案乙，符合 ReAct「规划→评审规划→执行→评审产物」节奏）**：
    - 第一级 · 编排层：生成 ContentDocument → structureChecker（纯代码，先行失败快）→ **内容设计评审**（章节编排 / 覆盖度 / 一致性）→ 条件边：major → fix 编排（带缺陷清单定向修正）→ 回内容设计评审（循环上限内）；pass → 进入第二级
    - 第二级 · 呈现层：并行派生内容讲解 + 习题 → **讲解评审 ‖ 练习评审**（并行，各自独立上下文，DeepSeek）→ aggregator 聚合（纯代码，输出结构化缺陷清单）→ 条件边路由：pass → 下一节点；minor → 放行 + 缺陷标记；major → fix 对应产物（带缺陷清单定向重生成）→ 回对应评审，**循环上限 2-3 轮**，超限降级落库 + 标记 + 通知（衔接人工节点）
    - 设计理由：编排阶段返工（改结构清单）成本远低于生成后重写正文——先锁骨架再填内容；major 编排缺陷的返工只重跑第一级，呈现级不重跑（成本优势）
  - **角色 × 维度矩阵**（评审注册表：注册项 = 角色 × 适用产物类型 × 适用维度）：
    | 评审角色 | 负责产物 | 适用维度 |
    | --- | --- | --- |
    | 内容设计评审 | 章节编排 / ContentDocument | 结构规范（代码）+ 内部一致性 + 覆盖度（对照学习目标的章节覆盖与分层递进） |
    | 讲解评审 | 内容讲解（AI 笔记） | 事实校验（回查转写原文）+ 讲解清晰度 + 形式偏好符合度 |
    | 练习评审 | 习题 + 实操建议 | 题目可解性 + 难度分布 + 与内容匹配度 + 依据标注完整性 |
  - **evaluator 注册表模式**：每个 evaluator = {角色、适用产物类型、专用 prompt（AgentPrompts 收口）、输入依赖声明、缺陷输出 schema（severity major/minor + location + evidence + suggestion）}；新增 Word/PPT/课件产物 = 注册新 evaluator，聚合/路由/fix 循环核心代码零改动；评审上下文按声明喂（EvaluationContext：artifact / artifactType / sources / userGoal / previousDefects）——事实校验拿原文、方向校验拿目标、一致性校验只看产物自身
  - **生成前置 · 用户画像采集（拍板新增）**：首次对某课程发起内容生成且无学习者画像时，AI 主动问 2-3 个问题（学习目的 / 知识基础 / 讲解形式偏好），不直接生成；内置「需求访谈」skill（grill me 形态）连环追问到信息充分；结果结构化存 course.learner_profile（JSON：goal/baseline/formatPreference），**课程内一次采集复用**；页面路径的 expectations 字段视为画像部分填充——「无画像跳过方向维度」的旧规则替换为「先问再生成」
  - **产物三类与评审归属**：内容讲解（流水线完成 / 惰性触发）→ 内容设计 + 讲解评审；习题（QuizAgent 惰性，阶段 4）→ 练习评审；实操建议（动手任务 / 练习计划）**延后**（拍板收敛，首批只做讲解 + 习题两类）
  - **模型口径**：评审统一 DeepSeek（AiModelService 解析链，不引入小模型分层）；每篇产物调用账单 = 1 次生成 + 3-4 次并行评审 + ≤2 次 fix
  - **形态区分**：评审 Agent 是图内任务节点（无状态、确定性触发）；与阶段 4 对话委派子代理（意图触发、有会话语义）两种形态并存
- **可选延展（按原锚点时机，非本阶段强制）**：人工节点 interrupt（笔记确认环节重启——2026-10-02 拍板搁置，重启需重新拍板）、Checkpointer 断点续跑（多用户/规模化后）
- 范围：网课流水线为主；B11 轻量转写链路短（≤30min 单片到数片），保持现有异步服务形态不强行 Graph 化

- 明确不做：MQ 跨队列编排、speaker 分离（列保留 NULL）、按人格拆 Agent、学习模式预设（2026-10-06 拍板不做）

## Graph 演进路线（2026-10-06 讨论，按「一次加一个」纪律）

**结论：Graph（StateGraph 状态机：固定骨架 + 动态路径）是本工单的正确终态骨架，但不是现在引入的框架。** Spring AI 官方核心无 Graph 编排能力；Graph 来自 Spring AI Alibaba 的 `spring-ai-alibaba-graph-core`（1.1.x 线：StateGraph / OverAllState / KeyStrategy / 条件边 / 并行边 / Checkpointer / 人工节点 interrupt / 流式），版本与 Spring AI 强绑定。

**现状校对（对照 CoursePipelineService）**：
- 顺序 Pipeline ✓（process() 单大方法，隐式顺序边）；B11 意图分流是流水线外（对话层）的第一个条件边
- **转写与画面通道实际是串行的**（音频先转写完、画面 OCR 才开始）——文档画的 `transcribe ‖ visual` 并行是真实改进点
- 循环（产物校验回退）✗、人工中断 ✗、断点续跑 ✗（失败重试全量重跑）

**三选项对比**：
| 选项 | 得 | 失 | 判断 |
| --- | --- | --- | --- |
| SAA Graph（graph-core） | 条件边/并行/循环/人工节点 interrupt/Checkpointer 全套现成 | 引入 SAA 依赖树；版本强绑定 Spring AI | **阶段 3 第一步 spike 验证** |
| LangGraph4j | Java 社区实现 | Spring 集成与活跃度弱于 SAA | 不优先 |
| 自研轻量状态机 | 零依赖；course 表加 stage 字段 + 幂等阶段方法 | interrupt / Checkpointer 要自己造 | spike 不过的回退项 |

**演进锚点表（一次加一个）**：
| Graph 能力 | 对应动作 | 时机 |
| --- | --- | --- |
| 条件边（QA 回退循环） | B26 阶段 1 产物校验+重试，方法内循环实现，不引框架 | 立即可做 |
| 并行 | 音频/画面两通道真并行（各自提交 courseExecutor 收集） | 顺手做 |
| 节点函数化 | process() 拆独立阶段方法（切片/Map/Reduce/Renderer） | 阶段 2 前置（并入阶段 2） |
| **引入 Graph 框架** | **SAA 兼容性 spike**：graph-core 试跑双节点 demo，验证 SAA 1.1.x ↔ Spring AI 1.1.8 + DeepSeek（OpenAI 兼容端点）共存；不过 → 自研 stage 状态机 | **阶段 3 第一步** |
| 人工中断（interrupt） | 笔记确认环节重启（2026-10-02 拍板搁置，**重启需重新拍板**） | 阶段 3 可选延展 / 公开部署前 |
| Checkpointer（断点续跑） | 状态序列化 + 节点幂等改造 | 阶段 3 可选延展 / 多用户规模化后 |
| Agent 节点（多 Agent 协作） | QuizAgent / ResearchAgent（agent-as-tool，见阶段 4） | 阶段 4 |

原则不变：**能工具就工具，能单次 LLM 就单次 LLM，需要自主决策才用 Agent 节点**；无论哪个选项，「节点函数化」都是前置工作，保证 SAA 与自研两个选项可随时互换。

## 复用与依赖

- 复用：course_transcript_segment（Raw 层）、QwenAsrTool / MediaUtils、AgentEventPushService（B11）、rag_search 向量库、B15 全局搜索
- 依赖：阶段 2 依赖阶段 1 的进度状态机；阶段 3 依赖阶段 2 的节点函数化（spike 失败则走自研 stage 状态机回退项）；阶段 4 依赖阶段 2（ContentDocument）与阶段 3（Graph 编排——QuizAgent 出题链路可复用 Graph 节点）；与 B19（PDF 摄取）、B23（Agent 工具扩展）交汇——Content Tools / 子代理委派落地即完成 B23 的部分项；ResearchAgent 后置依赖搜索 API 选型

## 成本与风险

- LLM 调用次数从 1 次/视频 → 惰性按需 N 次（Map-Reduce + 用户目标驱动），测试期成本可控但需记录单视频调用账单口径
- QA 评审账单口径（阶段 3）：每篇产物 = 1 次生成 + 3-4 次并行评审（DeepSeek 全量）+ ≤2 次 fix，全部统一 DeepSeek 无价差；用户画像采集（问询轮次）为纯对话消耗
- 生成链路重构（阶段 2）是中等规模改造：新表 + NoteGenerationService 改 Renderer，需回归网课全链路冒烟
- Graph 引入（阶段 3）是引入新依赖树 + 流水线迁移：spike 通过才执行，迁移期新旧链路并行冒烟（对照 video4/video5 双分支基线）
