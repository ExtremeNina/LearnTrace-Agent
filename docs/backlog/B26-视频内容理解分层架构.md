# B26 视频内容理解分层架构（产物校验 / ContentDocument / Graph 演进 / 多 Agent 委派）

- 优先级：P1（内容理解）　|　模块：网课流水线 / Agent / 笔记　|　来源：2026-10-05 用户提出架构设计（长视频转写与 AI 内容理解业务设计），经合理性分析后分期立项；2026-10-06 补充多 Agent 委派与 Graph 演进路线讨论结论
- 状态：待办（分三阶段，动工顺序由用户逐项指定；每阶段开工前走「工单流程节奏」设计关）

## 核心思想（用户原文）

> 视频只是输入，统一内容模型才是核心资产。确定性工作交给 Workflow / Service，非确定性决策交给 Agent。

四层解耦：媒体处理（FFmpeg/ASR/MQ，确定性）→ 原始转写（Raw Transcript，事实层不被 AI 修改）→ 内容理解（ContentDocument 语义层）→ 呈现（笔记 / Markdown / Word / PPT / 练习题，Renderer 派生）。

## 分析结论（2026-10-05，对照现状）

**认同**：确定性/非确定性边界（现状已遵循）；三层内容模型——当前最大缺口正是中间语义层（course_transcript_segment 直接单次 LLM 生成笔记，无 ContentDocument，换输出格式要重跑 LLM、知识点无独立实体、AI 对话无法引用章节）；不做大一统 Agent；人机协作确认（已有硬性规范）。

**修正**：
- MQ 跨队列链式编排（fan-in 聚合）当前规模不必要——单消费者内 courseExecutor 并行（帧 OCR 先例）天然有聚合点，拿 90% 收益付 10% 复杂度
- Map-Reduce 按转写字数**自适应**（阈值约 1.5 万字），不给 30min 级常见场景强加多倍 LLM 成本；跨 chunk 概念连续性是分段摘要的新风险
- ReAct 内容工具：`extractKnowledgePoints` 类工具若最终只映射固定 2-3 种编排，是 Renderer 参数而非 Agent；工具返回「句柄/摘要」而非大段产物（token 控制）；产物类生成走持久化
- 状态机：不新立 video_task 表——course 实体即任务载体，细化 status/加 stage 字段 + 复用 B11 推送基建（AgentEventPushService + 事件）即可

**文档未覆盖、落地要撞上的问题**：ContentDocument 生成时点建议**惰性**（首次消费触发，B13 简报模式）；多输入源归一（B19 PDF、笔记向量化应产出同一模型，否则语义层只服务视频）；ASR 无 speaker/confidence（保留列允许 NULL）。

## 阶段 1：产物校验 + 流水线细粒度进度（低成本高收益，先行）

- **产物校验 + 一次重试**：NoteGenerationService 生成后代码级校验——四段标题齐全、章节时间线时间戳存在于转写分段集合、知识点非空、正文/转写字数比合理；不合格带缺陷说明重生成一次，再不合格降级落库并标记；后续可加引用对齐（知识点段落回检索转写原文，低相似判无据）
- **进度状态机**：course.status 细化（AUDIO_EXTRACTED / TRANSCRIBING / ANALYZING / NOTE_GENERATING…）+ 进度清单事件（✓/●/○）复用 AgentEventPushService 推送
- 范围：网课流水线 + B11 对话转写共用校验

## 阶段 2：ContentDocument 落地（核心资产）

- 新表：content_document + sections（章节：起止时间/摘要）+ content_knowledge_points（知识点：归属章节/重要度/易错标记）
- 生成：转写字数超阈值自适应 Map-Reduce（chunk 语义切片 → 并行分析摘要/关键词/知识点/时间范围 → Reduce 章节合并）；惰性生成（流水线完成先出 Raw，首次消费触发理解）
- 改造：AI 笔记改为「从 ContentDocument 渲染」（Renderer 起步只做 Markdown 一个）；B19 PDF 摄取按同一模型产出
- 边界：Raw Transcript 永不覆盖，ContentDocument 可重生成

## 阶段 3：内容工具与多 Agent 委派（对话引用 + 派生内容）

- Content Tools 挂进对话 Agent：getContentDocument / getChapter / generatePractice 等（ToolContext 带 courseId/documentId/userGoal）
- AI 回答引用章节时间戳 + 「回到视频」跳转（CourseDetail AI 问答 tab 已有雏形）
- 练习题 / Flashcard Renderer（复用错题本与复习队列）
- **子代理委派（agent-as-tool，2026-10-06 讨论拍板）**：主对话 Agent 保持单入口不拆（持有会话记忆），按意图委派**无状态子代理**，委派形态 = 子代理封装为工具，长任务走 B11 异步模式（提交秒回 + 占位气泡 + 完成推送）：
  - QuizAgent：基于内部资料（题库 + 转写 + 笔记）出题 + 自检，每题标注依据来源（内部引用 = 转写分段 / 笔记段落）
  - ResearchAgent：**暂缓**（2026-10-06 拍板）——外部资料做测验（web_search + 网页正文抽取 + 引用标注）先留不做，待搜索 API 选型（博查/必应/Tavily，按次计费）与需求验证后再立项；QuizAgent 的依据来源规范预留外部引用（URL）扩展位
- 明确不做：MQ 跨队列编排、speaker 分离（列保留 NULL）、按人格拆 Agent、学习模式预设（2026-10-06 拍板不做）

## Graph 演进路线（2026-10-06 讨论，按「一次加一个」纪律）

**结论：Graph（StateGraph 状态机：固定骨架 + 动态路径）是本工单的正确终态骨架，但不是现在引入的框架。** Spring AI 官方核心无 Graph 编排能力；Graph 来自 Spring AI Alibaba 的 `spring-ai-alibaba-graph-core`（1.1.x 线：StateGraph / OverAllState / KeyStrategy / 条件边 / 并行边 / Checkpointer / 人工节点 interrupt / 流式），版本与 Spring AI 强绑定。

**现状校对（对照 CoursePipelineService）**：
- 顺序 Pipeline ✓（process() 单大方法，隐式顺序边）；B11 意图分流是流水线外（对话层）的第一个条件边
- **转写与画面通道实际是串行的**（音频先转写完、画面 OCR 才开始）——文档画的 `transcribe ‖ visual` 并行是真实改进点
- 循环（产物校验回退）✗、人工中断 ✗、断点续跑 ✗（失败重试全量重跑）

**三选项对比**：
| 选项 | 得 | 失 | 判断 |
| --- | --- | --- | --- |
| SAA Graph（graph-core） | 条件边/并行/循环/人工节点 interrupt/Checkpointer 全套现成 | 引入 SAA 依赖树；版本强绑定 Spring AI | **阶段 2 动工前 spike 验证** |
| LangGraph4j | Java 社区实现 | Spring 集成与活跃度弱于 SAA | 不优先 |
| 自研轻量状态机 | 零依赖；course 表加 stage 字段 + 幂等阶段方法 | interrupt / Checkpointer 要自己造 | spike 不过的回退项 |

**演进锚点表（一次加一个）**：
| Graph 能力 | 对应动作 | 时机 |
| --- | --- | --- |
| 条件边（QA 回退循环） | B26 阶段 1 产物校验+重试，方法内循环实现，不引框架 | 立即可做 |
| 并行 | 音频/画面两通道真并行（各自提交 courseExecutor 收集） | 顺手做 |
| 节点函数化 | process() 拆独立阶段方法（切片/Map/Reduce/Renderer） | 阶段 2 前置 |
| **引入 Graph 框架** | **SAA 兼容性 spike**：graph-core 试跑双节点 demo，验证 SAA 1.1.x ↔ Spring AI 1.1.8 + DeepSeek（OpenAI 兼容端点）共存；不过 → 自研 stage 状态机 | 阶段 2 动工前 |
| 人工中断（interrupt） | 笔记确认环节重启（2026-10-02 拍板搁置，**重启需重新拍板**） | 公开部署前 |
| Checkpointer（断点续跑） | 状态序列化 + 节点幂等改造 | 多用户/规模化后 |
| Agent 节点（多 Agent 协作） | QuizAgent / ResearchAgent（agent-as-tool，见阶段 3） | 内容理解层就绪后 |

原则不变：**能工具就工具，能单次 LLM 就单次 LLM，需要自主决策才用 Agent 节点**；无论哪个选项，「节点函数化」都是前置工作，保证 SAA 与自研两个选项可随时互换。

## 成本与风险

- LLM 调用次数从 1 次/视频 → 惰性按需 N 次（Map-Reduce + 用户目标驱动），测试期成本可控但需记录单视频调用账单口径
- 生成链路重构（阶段 2）是中等规模改造：新表 + NoteGenerationService 改 Renderer，需回归网课全链路冒烟
