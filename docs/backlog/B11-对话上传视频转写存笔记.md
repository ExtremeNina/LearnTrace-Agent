# B11 对话上传视频：语音转写 + 保存笔记

- 优先级：P1（内容输入）　|　模块：Agent 对话 / 网课 ASR / 笔记　|　来源：2026-10-04 用户提出（取代旧「方案 B：轻量抽帧预览 + 确认后归档」讨论，即原 agent.md 当前待办 6）
- 状态：待办（可行性已确认，四项方针待拍板后走设计关）

## 需求（用户口径，2026-10-04）

- 对话输入框支持上传视频，仅限 30 分钟以下
- 只做语音转写：不抽帧 OCR、不做 LLM 整理（与网课流水线区分的轻量路径）
- 转写成功后用户可保存到「笔记整理」；未指明分组时默认新建分组 + 新笔记存放转写内容，分组名 / 笔记名由 LLM 命名
- 保存属创建用户数据，须对话明确确认后才执行（硬性规范）

## 可行性盘点（2026-10-04 代码探查结论）

- ✅ `QwenAsrTool` 与课程实体零耦合（`transcribeSegments` 返回句级毫秒时间戳，输入 OSS 公网 URL），直接复用
- 🔧 需从 `CoursePipelineService.process()` 抽出「FFmpeg 抽音频 + 280s 分片 + 时间戳偏移合并」为独立转写服务（抽出来后 B20 语音笔记近零成本接入）
- ✅ 笔记侧 `NoteService.createGroup / createNote / updateContent` 现成（注意 createNote 固定 sourceType=0，转写来源需扩展标记或照 NoteGenerationService 直插模式）
- 🔧 缺 create_note Agent 工具（范式照抄 QuestionSaveTool；与 B23 规划重叠，B11 先做则 B23 该项顺带完成）
- 🔧 消息模型：Message 仅 imageUrl 且被 OCR 解题流水线占用（带图会切解题 prompt），需新字段（videoUrl）或新 msgType，不能复用图片字段
- ✅ 上传复用网课 500MB 服务端中转 OSS 链路（格式白名单 mp4/mov/mkv/avi/webm/m4v 已有）
- 🔧 时长限制前后端均无，需新增（`ffprobeDurationSec` 现成）
- 进度反馈：现状为 8s 轮询状态字段；agentSocket 可推送但缺 userId→session 注册表与新事件类型（两处扩展，成本不大）

## 规模参考

30min ≈ 7 个 280s 分片，串行数分钟；失败处理沿用现有（nack 不重投，对话内提示）；`ASR_RESPONSE_HAVE_NO_WORDS` 静音降级已有。附带收益：保存为笔记后自动走现有向量化管道，转写内容即可被 rag_search 检索。
